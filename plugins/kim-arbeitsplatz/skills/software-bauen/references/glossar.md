# Glossar

Nachschlagen, wenn ein Begriff im Gespräch nötig wird. **Erklär ihn beim ersten Mal in einem
Halbsatz und benutz ihn dann ruhig weiter** — Menschen wollen nicht dumm gehalten werden, sie
wollen nur einmal wissen, was gemeint ist.

| Begriff | In einem Satz |
|---|---|
| **API / Schnittstelle** | Eine Tür, durch die ein anderes Programm mit deinem redet — kein Bildschirm, nur Daten. |
| **Token / Schlüssel** | Ein langes Passwort für Programme statt für Menschen. |
| **Hash** | Ein Passwort so verrechnet, dass man es prüfen, aber nicht zurücklesen kann. |
| **`.env`** | Die Datei mit den Zugangsdaten, die nie mit hochgeladen wird. |
| **Git / Commit** | Ein Speicherstand mit Notiz, zu dem man zurückkehren kann. |
| **`.gitignore`** | Die Liste der Dateien, die beim Hochladen ausgelassen werden. |
| **Repository** | Der Ablageort des Codes, meist bei GitHub. Steht immer auf privat. |
| **Mandant** | Eine Firma oder Abteilung, deren Daten von den anderen getrennt bleiben müssen. |
| **Authentifizierung** | Wer bist du? (Anmeldung) |
| **Autorisierung** | Was darfst du? (Berechtigung — die andere Hälfte, die oft fehlt) |
| **Row Level Security** | Die Datenbank selbst lässt jeden nur an die eigenen Zeilen. |
| **Reverse Proxy** | Der Türsteher vor der Anwendung: nimmt alle Anfragen entgegen und reicht nur weiter, was durchdarf. |
| **VPN** | Ein Tunnel ins Firmennetz, damit etwas nicht öffentlich erreichbar sein muss. |
| **Port** | Eine nummerierte Tür am Server. Offene Türen, die niemand braucht, macht man zu. |
| **SQL-Injection** | Jemand tippt statt eines Namens einen Datenbankbefehl ein — und er wird ausgeführt. |
| **XSS** | Dasselbe mit Programmcode, der dann im Browser der nächsten Person läuft. |
| **OWASP Top 10** | Die anerkannte Liste der zehn häufigsten Sicherheitslücken in Webanwendungen. |
| **Prompt Injection** | In einem Text, den die KI verarbeitet, stehen versteckte Anweisungen — und sie befolgt sie. |
| **Rate Limit** | Eine Bremse: nur so viele Versuche pro Minute. |
| **Container / Docker** | Die Anwendung samt allem, was sie braucht, in einer Kiste — läuft überall gleich. |
| **Sandbox** | Ein abgeschotteter Bereich, in dem Fehler nichts kaputt machen können. |
| **POC / MVP** | Machbarkeitsnachweis · kleinste nützliche Version für echte Nutzer. |
| **Log** | Das Protokoll: wer hat wann was gemacht. |
| **Monitoring** | Die Überwachung, die meldet, wenn etwas steht. |
| **Health Check** | Ein Prüfpunkt, den man abfragen kann: "Läufst du noch, und kommst du an deine Datenbank?" |
| **3-2-1-Regel** | Drei Kopien, zwei Orte, eine außer Haus. |
| **Härten** | Alles abschalten und zumachen, was nicht gebraucht wird. |
